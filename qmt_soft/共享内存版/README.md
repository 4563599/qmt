## 盘中与盘后执行开关（2026-10-27）

在 QMT 中运行的 `qmt_shm_bridge.py` 顶部设置：

```python
CHECK_TRADING_TIME = True
```

- `True`：外部盘中策略仅在工作日 09:25–11:30、13:00–15:05 执行常规扫描，沿用原策略的时间规则。
- `False`：外部盘中策略不检查交易时段，盘前、午休、盘后都继续按定时器循环扫描，不限制盘后次数。
- 配置 `REFERENCE_DATE` 的历史模式仍按原策略只执行一次，不受该开关限制。

行情桥通过共享内存发布这个参数，外部程序在原盘中策略初始化前和后续定时驱动时读取它，优先于原文件中的同名值。无需在 QMT 中执行原 `盘中.py`。THS 没有这个同名开关，其执行时间规则保持原样。

**首次使用本次更新时，关闭旧外部程序，手动停止 QMT 的行情桥，将更新后的 `qmt_shm_bridge.py` 重新导入／同步到 QMT 编辑器后运行，再启动一个外部程序入口。** 此后在 QMT 编辑器修改开关，也需要重新运行行情桥，并重启外部程序。只修改磁盘文件不会改变已经运行的 QMT 策略。

QMT 显示 `[SHM CONFIG] CHECK_TRADING_TIME=True`，外部程序显示 `[CONFIG][panzhong] CHECK_TRADING_TIME=True; original execution rules retained`，表示配置已传递。连接旧版行情桥的外部程序会明确提示回退到原文件的配置。

这个开关只控制盘中策略是否扫描，不关闭行情桥的心跳或行情接口。QMT 内仍只运行行情桥；选股、写 Redis、发钉钉由单独启动的外部 Python 完成。**仅运行行情桥而不启动外部程序，不会产生选股结果。**

**仅在行情桥与外部程序版本一致时，盘中单独版切换为双策略可保留行情桥运行，只关闭旧外部窗口，再启动“启动盘中与THS外部程序.cmd”。本次新增时间开关需先按上文更新 QMT 行情桥。**

## 其他集中配置入口（2026-10-27）

行情桥顶部现在可配置：

| 参数 | 用途 | 默认行为 |
|---|---|---|
| `REFERENCE_DATE` | 两份策略的参考日期 | `None` 沿用各自原配置；`""` 实时；`"20261023"` 历史模式 |
| `PANZHONG_ENABLED`、`THS_ENABLED` | 两份策略分别启停 | 都为 `True`，实际运行范围仍由选择的启动入口决定 |
| `PANZHONG_HISTORY_RELOAD_TIME` | 盘中每天刷新历史的时间 | `09:15:00` |
| `THS_HISTORY_RELOAD_TIME` | THS 每天刷新历史的时间 | `09:25:00` |
| `PANZHONG_OPTIONS` | 原盘中策略的 20 项非敏感配置 | 每项 `None` 表示沿用原文件，不是关闭功能 |
| `THS_OPTIONS` | 原 THS 策略的 9 项非敏感配置 | 每项 `None` 表示沿用原文件 |

例如在 `PANZHONG_OPTIONS` 中把 `"DINGTALK_ENABLED": None` 改为 `"DINGTALK_ENABLED": False`，可关闭外部盘中钉钉提醒；把 `"TIMER_INTERVAL_TEXT": None` 改为 `"TIMER_INTERVAL_TEXT": "3nSecond"`，可改为每 3 秒触发扫描。THS 对应频率字段为 `PUBLISH_INTERVAL_TEXT`。支持 `1nSecond` 至 `3600nSecond`，不会并发补跑错过的轮次。

历史天数、K 线长度、读取批次、TTL、日志目录及盘中阈值等都列在对应字典中。默认不改变任何筛选阈值；只有填写非 `None` 值才覆盖原配置。修改 K 线长度时会联动历史 K 线长度和默认历史请求长度，配置相互矛盾时会在初始化前报错。

Redis 地址、密码、输出 key、钉钉地址和消息路由仍从外部原文件读取，不复制进 QMT 行情桥。原选股、清洗、K 线、涨停梯队、推送重试、去重和日志计算函数直接保留；THS 原本没有时间开关，其盘后启动时初始化更新一次、定时发布遵守原时段的行为不变。

日期、启停、频率、刷新时间及其他配置修改后都需要重启外部程序；行情桥改动还需要同步到 QMT 并重新运行。已经启动的策略不热切换参考日期，避免旧缓存污染新日期。`--no-dingtalk` 始终优先于行情桥中的推送开关。性能采集器会同步读取日志目录和参考日期配置。

完整核对说明见 `docs/参数与功能核对.md`。本次更新**没有增加“盘后只执行一次”的限制，也没有增加盘前或午休等待规则**。

## 操作步骤

### 1. 在 QMT 中新建行情桥策略

在 QMT 的 Python 策略编辑器中新建或导入本目录的 **`qmt_shm_bridge.py`**，策略名建议使用 **`qmt_shm_bridge`**。整个文件导入即可，不用修改 QMT 安装目录下的 Python 库，也不用添加搜索路径。

由你手动运行这份行情桥策略。正常情况下日志显示：

```text
[SHM READY] channel=panzhong_v1; start external check program.
```

这份策略只提供行情，不运行原盘中扫描，不连接 Redis，不请求钉钉，也没有下单或撤单接口。

若显示 `[SHM FAILED]`、`mmap` 被禁止或类似权限错误，请保留错误信息；此时不要启动正式扫描。

### 2. 双击“检查共享内存.cmd”

保持 QMT 已登录、行情桥策略运行，双击本目录的 **`检查共享内存.cmd`**。

它会等待最多 60 秒，检测共享内存握手、平安银行实时行情和日 K 线。成功显示：

```text
[CHECK OK] Anonymous shared memory; sample=000001.SZ; tick=yes; history_rows=...
[CHECK ONLY] Scanner/Redis/DingTalk were not started.
```

检测程序不加载原盘中策略、不连接 Redis、不发送钉钉。

### 3. 双击“启动盘中与THS外部程序.cmd”

先关闭旧的外部盘中程序窗口；保留 QMT 中的新行情桥策略运行。QMT 内的旧 `PANZHONG` 与 `ths筛选` 均不要运行。

双击 **`启动盘中与THS外部程序.cmd`**，看清提示后按 **Y** 开始。它会再次检查行情桥，通过后从上级目录分别加载原 `盘中.py` 和 `ths筛选.py`，使用各自原文件里的 Redis、提醒和日志配置。

外部程序内有两个独立工作线程，各自持有原脚本的全局状态、历史缓存和定时器。两者通过同一 RPC 客户端串行取得 QMT 行情，计算与发布互不共用策略状态。正常初始化完成后分别出现 `[RUNNING][盘中]` 和 `[RUNNING][THS]`。

外部程序负责计算、写 Redis、发送满足原条件的钉钉提醒。运行期间保持 QMT 和这个控制台窗口开启。同一共享内存频道只运行一个外部程序；不要同时打开单策略和双策略入口，以免重复运行。桥中断或任一策略出现未捕获错误时，外部程序明确报错并停止，避免误以为两者仍在正常运行。

如只想运行一种，原 **`启动盘中外部程序.cmd`** 仍保留，另有 **`启动THS外部程序.cmd`**。三个正式入口任选其一。

此前盘中单独版已由用户启动并完成实际初始化，且一条授权测试钉钉已确认收到。本次双策略扩展没有自动关闭旧程序、启动新生产实例、写生产 Redis 或额外发送消息。

## 停止与恢复

- 停止外部扫描：在外部控制台按 **Ctrl+C**，或关闭该窗口。
- 停止行情桥：在 QMT 中手动停止 `qmt_shm_bridge` 策略。
- QMT 桥停止、心跳失效或桥实例重启，外部程序会报错退出；重启桥后需要重新启动外部程序。
- 三份共享内存约占用 33 MiB 的映射空间，另有序列化和行情对象开销；双方退出后由 Windows 回收，不产生行情交换文件。
- 桥默认每秒轮询请求；真实端到端延迟和全市场初始化速度，需在 QMT 中验证。
- 若出现 Windows 访问被拒绝，检查 QMT 和外部程序是否在同一 Windows 用户、同一登录会话且权限一致；不需要修改系统代理。

## 新桥仍提示“非法 IP：Redis 地址”时

`qmt_shm_bridge.py` 本身没有 Redis 地址、Redis 库或 HTTP 客户端。Redis、钉钉和日志只在 `external_runner.py` 启动的外部 Python 中执行。

**停止旧策略，不一定会释放该策略在 QMT 进程内建立的 Redis 连接。** 新桥启动时，客户端仍可能检测到这条旧连接。

2026-10-26 的现场检查确认：QMT 进程在 20:53:02 建立的 Redis 连接，直到 21:20 新桥启动后仍为 ESTABLISHED；新桥两次正常输出 `[SHM READY]`。这说明不能仅凭同一客户端弹窗认定新桥正在连接 Redis。

遇到这种情况，由你手动完整退出并重开 QMT，清除旧会话；重开后只运行 `QMT_SHM_BRIDGE`，不要运行旧 `PANZHONG` 或 `ths筛选`。随后运行“检查共享内存.cmd”，再启动双策略外部程序。两份原策略都应在外部执行。
