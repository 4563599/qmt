# QMT 策略控制台

入口：`C:\Users\lyy\Desktop\qmt\共享内存版\打开策略控制台.vbs`。

## 每天使用

1. 在 QMT 中运行 `qmt_shm_bridge.py`，保持 QMT 开着。
2. 如果旧的外部程序黑窗口仍在运行，先关闭旧窗口。新界面会检测重复运行，不会结束或接管旧进程。
3. 双击 `打开策略控制台.vbs`，点击“启动”。此操作等价于原来双策略 CMD 中选择 Y，会实际运行原策略、写入 Redis，并沿用原推送设置。
4. 点击“停止”正常结束本界面启动的外部程序；点击“退出”或关闭窗口，会先确认是否停止。不会停止 QMT。

## 状态与日志

- 顶部显示共享内存心跳、两份策略的初始化/运行状态、外部进程 PID 和运行时间。
- “盘中日志”“同花顺日志”“系统日志”分别显示对应输出，可查找、筛选、选择和复制文字。选择文字不会暂停扫描。输出按线程和策略来源标记，不根据中文/英文或最近一行猜测来源；后台推送线程的日志也能分开。
- “异常详情”显示错误、警告和 Python 堆栈。异常退出还显示退出码、命令、进程 PID 和日志路径。
- “清空显示”仅清空界面，不删除本地日志，不清空 Redis 或推送去重记录。
- “打开日志”打开本次日志目录。日志保存在 `共享内存版\logs\launcher\YYYYMMDD\`。`ui_*.log` 是界面监控记录；`*.panzhong.log`、`*.ths.log`、`*.system.log` 是分开的关键日志，不带来源后缀的时间日志是合并的关键日志；`*.raw.log` 保存完整原始输出，包含界面省略的重复明细。
- 屏幕日志使用有限缓冲，超出时会提示省略较早内容；完整输出仍在 `.raw.log` 中。
- 心跳不可用、运行期超过90秒没有新输出会提示警告。盘后按原配置正常停止扫描时不会仅因无日志误报警。行情请求在有效超时期限内等待时不会被误判为桥接掉线。
- 不自动重启异常程序，避免重复推送或覆盖数据。修复后可人工重新启动。

## 关键日志规则

- 初始化开始、股票名称/连板基础资料、日K开始和分批加载、初始化完成均保留。读取基础资料每约5秒更新一次“完成数/目标数”，补齐此前读取北交所连板资料时的长时间空白。
- 同一进程、同一交易日、同一来源的同一只股票，历史数据缺失只提示一次。次日或新进程重新汇报；新出现的缺失股票立即提示。
- 已知历史缺失引起的重复“构建失败”列表，以及每轮重试仍为0成功的重复批次不再刷屏。实际重试继续，历史读取条件和失败处理不变。
- 盘中和同花顺的运行结果各保留首轮，之后每30秒一条摘要。逐轮条件拆解、入选明细、重复Redis成功写入和重复性能分项只保留在原始日志中。
- 相同性能超时提醒每5分钟最多显示一次；它是警告，不再因为原文标为ERROR就累计成界面程序错误。真实异常、Redis/网络失败、错误堆栈和钉钉推送结果仍及时显示。
- 两份原策略的详细文件日志、性能CSV、Redis逐轮性能记录不删减、不改写；关键模式只筛选桌面控制台的显示和关键日志留档，防止影响性能页面。

日志规则不改变扫描频率、历史重试、选股结果、Redis字段/键名或推送。更新后重新启动外部程序才能启用；正在运行的实盘进程不会被自动替换。

## 停止边界

界面通过外部 Python 的私有标准输入管道发送 STOP；这不是 QMT 内的文件或网络连接。外部行情请求可取消，策略线程退出后才释放共享内存连接。

控制管道采用非阻塞轮询，不在等待命令时长期占用 Windows 标准输入锁，避免与 NumPy 初始化冲突。2026-10-27 已增加真实子进程自检回归，覆盖“界面启动、等待停止指令、导入 NumPy/pandas、读取隔离行情、正常退出”的完整链路。修复后只需停止并重新启动外部程序，无需重新导入 QMT 桥接。

正常停止超过15秒时，停止按钮变为“强制结束”，必须再次确认。强制结束只针对本界面创建的外部进程，可能中断当轮尚未完成的 Redis 写入，不会清空已有数据，也不会停止 QMT。

关闭旧 CMD 窗口和本次切换方式一致。新的桌面控制台不改变两份原策略文件、任何选股阈值、Redis 字段/键名或原执行时段。`CHECK_TRADING_TIME=False` 依然盘中盘后循环；指定历史参考日期依然只运行一次。

## 启动排查

入口使用 `C:\Program Files\Python311\pythonw.exe`，不弹出黑窗口。运行环境仍需要原来使用的 pandas、redis、requests 和 Python 自带的 tkinter；没有额外界面依赖。

界面初始化失败会弹窗，并尝试写入 `logs\launcher\startup_error.log`。必要时用 Python 3.11 执行 `launcher_gui.py` 查看启动错误。仅预览界面、不运行任何选股程序：

```powershell
python -X utf8 launcher_gui.py --demo
```

桌面控制台无需重新导入 QMT 策略：新增取消机制用于外部进程中的行情客户端，QMT 内桥接的协议、行情处理和定时行为没有改变。

## 交易日09:15自动打开并启动

Windows 计划任务名：`QMT_StrategyConsole_0915`。任务每周一至周五09:15触发短时调度程序；程序使用现有 Tushare 授权读取上交所 `trade_cal`，核对真实交易日后才打开界面并启动。不会新建 Codex 定时聊天，不依赖 Codex 保持打开。

- 节假日和周末不自动启动，不把“星期一至五”直接当成交易日。
- 已缓存2026年完整365天日历。日历保存在 `runtime/calendar/sse_年份.json`，定期更新；网络不可用时可使用已校验的完整缓存。没有有效日历时取消自动启动并记录错误，不盲目按工作日执行。
- 如果控制台已经打开，计划任务向现有窗口发送一次启动请求；已有扫描进程则不重复启动。计划任务入口会尽快退出，允许第二天再次发出请求，界面跨夜打开也不会挡住第二天的触发。
- QMT桥接未就绪时，窗口等待心跳，连接后自动启动。可点击“停止”取消等待。超过当日15:05或日期变化时取消，不在深夜补跑。
- 自动启动仍沿用 `CHECK_TRADING_TIME` 和原策略配置：09:15启动不等于提前改变原扫描时段。
- 电脑须开机并已登录当前Windows账户。不会自动登录Windows或QMT，不会启动/替换QMT桥接。睡眠或关机时不保证准点执行；当天交易时段内恢复登录后可由系统补触发。
- 调度日志：`logs/launcher/YYYYMMDD/scheduled_start.log`。日历错误、跳过、等待和重复启动检查都有记录。

更换代码目录后，可重新运行 `install_daily_start.ps1` 更新任务；`-VerifyOnly` 只查看配置，不启动扫描。更新界面后应在方便时停止、关闭并重开一次控制台，当前已运行的旧窗口不会热替换代码。
