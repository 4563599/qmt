# 参数与功能核对（2026-10-27）

## 执行规则不变

外部程序直接加载 `盘中.py` 和 `ths筛选.py`。盘中源码于2026-10-27按用户要求追加“两次涨停间阴线≤1”标记，并修复行情日期解析；THS源码未改动。QMT 内只运行 `qmt_shm_bridge.py`，不运行两份旧策略。此处此前“两个原文件均未修改”的说明仅对应共享内存迁移阶段；当前版本以本次明确授权的源码修订为准。

盘中策略严格保留以下规则，没有新增盘后次数限制：

| 配置 | 盘中 | 盘后 |
|---|---|---|
| `CHECK_TRADING_TIME=True` | 循环扫描 | 不扫描 |
| `CHECK_TRADING_TIME=False` | 循环扫描 | 继续循环扫描 |
| 指定 `REFERENCE_DATE` | 历史模式只执行一次 | 历史模式只执行一次 |

`False` 也不限制盘前和午休。时段边界直接使用原程序函数，没有替换扫描函数、K 线函数或阴阳线判断。

THS 原本没有 `CHECK_TRADING_TIME`；其定时发布遵守原时段，盘后启动时初始化更新一次，历史模式只执行一次。行情桥没有给 THS 额外引入盘中策略的时间过滤或无限盘后发布。

## 已补齐的入口

- 共同参考日期：`REFERENCE_DATE`，`None` 沿用各自原配置，空字符串使用实时模式，八位日期字符串使用原历史模式。
- 分别启停：`PANZHONG_ENABLED`、`THS_ENABLED`。启动入口决定请求哪份策略，开关可禁用其中一份，不会擅自启动未选择的策略。
- 历史刷新：盘中默认 `09:15:00`，THS 默认 `09:25:00`，可分别修改。
- 定时频率：`TIMER_INTERVAL_TEXT`、`PUBLISH_INTERVAL_TEXT`，支持每 1 至 3600 秒触发。

`PANZHONG_OPTIONS` 中的配置：

| 分类 | 参数 |
|---|---|
| 原筛选阈值 | `MIN_REALTIME_GAIN_PCT`、`HIGH_GAIN_THRESHOLD_PCT`、`MAX_YIN_COUNT_20`、`MIN_HIGH_GAIN_COUNT_10D`、`MIN_LOW_ABOVE_MA5_COUNT_10D`、`PZ1_MAX_YIN_COUNT_20` |
| 历史与 K 线 | `HISTORY_REQUEST_DAYS`、`KLINE_TOTAL_DAYS`、`HISTORY_BATCH_SIZE` |
| 调度与有效期 | `TIMER_INTERVAL_TEXT`、`REDIS_TTL_SEC` |
| 钉钉开关与重试 | `DINGTALK_ENABLED`、`DINGTALK_RETRY_COUNT`、`DINGTALK_PERSIST_RETRY_COUNT`、`DINGTALK_PERSIST_RETRY_MAX_DELAY_SEC`、`DINGTALK_MAX_YIN_COUNT_20` |
| 日志 | `LOG_ENABLED`、`LOG_SELECTED_LIMIT`、`LOG_BASE_DIR`、`STRATEGY_DIR_NAME` |

`THS_OPTIONS` 中的配置：

| 分类 | 参数 |
|---|---|
| 历史与 K 线 | `REDIS_QMT_KLINE_DAYS`、`HISTORY_BATCH_SIZE`、`HISTORY_REQUEST_DAYS`、`CLOSE_BAR_REFRESH_SEC` |
| 调度与有效期 | `PUBLISH_INTERVAL_TEXT`、`REDIS_QMT_KLINE_TTL_SEC`、`REDIS_STATUS_TTL_SEC` |
| 日志 | `LOG_BASE_DIR`、`STRATEGY_DIR_NAME` |

以上字典值默认全部为 `None`，不覆盖原设置。`KLINE_HISTORY_DAYS` 是派生值，随 `KLINE_TOTAL_DAYS` 自动更新，不需要重复配置。

## 原功能保留方式

| 功能 | 保留方式 |
|---|---|
| PZ、PZ1、QY1、QY2 的选股与字段 | 直接调用原计算与发布函数，默认阈值不变 |
| 全市场涨停天梯、北交所与连续涨停统计 | 原逻辑保留，原行情接口经共享内存传输 |
| THS 输入股票池、板块、清洗、分组与 K 线 | 原函数保留，包括原 Lua 增量更新及回退逻辑 |
| 参考日与昨收校验、收盘 K 线覆盖 | 原日期和报价验证函数不替换 |
| 历史缓存、每日报价刷新、锁与忙轮跳过 | 原逻辑保留，定时器只负责触发原回调 |
| 钉钉路由、消息、发送重试、去重与记录 | 原函数和原 Redis key 不变，`--no-dingtalk` 优先禁止推送 |
| 运行日志、性能 Redis、THS CSV | 原记录函数保留，性能采集器跟随配置后的日志目录和参考日期读取 |

没有把密码、钉钉地址或 Redis 输出 key 放入共享内存配置。这些参数和消息路由、标签定义、性能列结构继续从外部原源码读取，因此不是缺失功能；也避免在 QMT 内运行文件、Redis 或 HTTP 操作。
